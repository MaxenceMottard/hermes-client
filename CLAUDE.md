# CLAUDE.md

Instructions for Claude Code in this repository.

## Project

Native SwiftUI client (iOS 27 / macOS 27) for a self-hosted Hermes Agent instance (OpenAI-compatible API). Personal use only. The work plan lives in the GitHub milestones and issues (M0 to M6).

## Language

Everything in the repository is written in English: code, comments, tests, docs, commit messages, PRs and issues.

## Architecture

- `HermesKit/`: local SPM package holding all the business logic, testable without UI.
  - `HermesAPI`: HTTP client (`URLSession`) for the session endpoints (`/api/sessions`), SSE parsing (`URLSession.bytes`), Codable models, typed errors.
  - `HermesChat`: conversation logic. Every conversation is a session stored on the Hermes instance (created, listed, renamed, deleted and continued through `/api/sessions`); the app keeps no copy.
  - `HermesStore`: SwiftData persistence of the conversations saved on the device by earlier versions of the app. They are read-only now.
  - `HermesSecurity`: Keychain wrapper, optional iCloud Keychain sync. M4.
- The app (`App/`: views, navigation, dependency injection) contains UI only. The Xcode project is generated by Tuist from `Project.swift`: never commit or edit the `.xcodeproj` / `.xcworkspace`, change the manifest and regenerate instead.
- The API client is built from an explicit configuration (URL + key). No global singleton.

## Conventions

- Swift 6, strict concurrency. `swiftLanguageModes: [.v6]`.
- Concurrency: `async/await`, `AsyncThrowingStream` for streaming, `Sendable` wherever a value crosses an actor boundary.
- Observation: `@Observable`, not `ObservableObject`.
- Tests: Swift Testing (`import Testing`, `@Test`, `#expect`). Network mocked through a custom `URLProtocol`. SSE fixtures stored in files.
- No third-party dependencies. Apple frameworks only.
- No secrets, real URLs or keys in code, tests or fixtures. Use `https://hermes.example.test` in tests.
- POST requests are never retried automatically. Generous timeouts (an agent request can take ~30 min).

## Commands

```sh
# Tooling (Tuist, version pinned in mise.toml)
mise install

# HermesKit package tests (swift test --package-path HermesKit)
mise run test

# Generate the Xcode project, then build the iOS or macOS app
mise run generate
mise run build
mise run build-mac

# App tests on an iOS 27 simulator (set IOS_DESTINATION to pick another simulator)
mise run test-app
```

CI: `.github/workflows/ci.yml` runs the HermesKit tests and builds the app for iOS and macOS on every PR and on `main`, on the `xcode-27` runner (macOS 27 + Xcode 27 preview image). App tests are slow and add little since the business logic lives in HermesKit, so they only run locally via `mise run test-app`.

## Git

- One issue = one branch = one PR. Branch `feat/<m>-<slug>` or `fix/<slug>`.
- Conventional Commits, small and clear.
- Never mark an issue Done unless its acceptance criteria are met and tests are green.

## Open questions

Items tagged `needs-verification` in the issues are assumptions about the Hermes API (health check path, `GET /v1/models`, iOS background behavior). Do not hard-code these assumptions without verifying them, and keep an abstraction that is easy to adjust.
